# True POS (demo)

An offline-first point-of-sale demo for a liquor shop chain. Four roles (cashier, manager, office, owner) run on generated dummy data held in the browser (IndexedDB). There is no backend and no real data.

React 18, Vite, TypeScript, Dexie, and a Workbox service worker (vite-plugin-pwa) for offline use.

## Run it on your computer

```sh
npm i
npm run dev          # http://localhost:5173, for working on the code
npm test             # unit and component tests
```

The offline PWA only works in the built app, because the service worker is not installed by the dev server:

```sh
npm run build
npm run preview      # http://localhost:4173
```

End-to-end checks (Chromium, 1280 x 800). They build nothing themselves, so run `npm run build` first. The first time, install the browser with `npx playwright install chromium`:

```sh
npm run build && npx playwright test
```

The first visit builds the dummy data and takes a few seconds. To start over, open the demo panel (Ctrl+Shift+D, or tap the logo three times) and choose Reset demo data. A browser that opened an older build keeps its old data, so reset it once after updating.

## Demo PINs

| Cashier | `1111` |
| Manager (one, chain-wide) | `2222` |
| Office | `3333` |
| Owner | `4444` |

The login screen shows them under "Demo". These are demo PINs for dummy staff, not real accounts.

Manager and Office share one back-office app. The manager also closes shifts and locks the day, runs prices and offers, voids bills, sets practice mode, and sees Shops & staff, where a new PIN can be set for anyone.

## About the data

Every bill, stock count, delivery, member and shop figure is generated by `src/seed/generate.ts` from a fixed seed, so each browser gets the same shops. The only real data in the repository is the product list (name, size, pack and MRP) in `src/seed/catalogue.json`. Do not add real sales, stock or customer data, PDFs or client documents: this repository is public.

## Deploying

Live demo: https://true-pos.muthannamandanna8.workers.dev

It runs as a Cloudflare Worker that only serves the built files (`wrangler.jsonc`; Pages projects now deploy as Workers). It lives in the True-spirits Cloudflare account, as its own Worker, separate from the customer app. To deploy a new build:

```sh
npx wrangler login     # once per machine
npm run build
CLOUDFLARE_ACCOUNT_ID=<True-spirits account id> npx wrangler deploy
```

`npx wrangler whoami` lists the account ids. After a deploy, open the URL on a tablet, install it as an app, turn the wifi off, and check that billing still works.
